# 创作罐头热点页 F12 分析指南

目标页面：`https://www.czgts.cn/v1/hots/popular`（以及 network、article）

只有分析清楚页面如何加载数据，才能和「你要的内容」精准匹配。请按下面步骤在浏览器里用 F12 做一次完整分析。

---

## 一、确认数据来源：是接口还是纯前端渲染

### 1. 打开 Network（网络）面板

1. 打开 `https://www.czgts.cn/v1/hots/popular`
2. 按 **F12** → 切到 **Network（网络）**
3. 勾选 **Preserve log**（保留日志），避免翻页/切换时请求被清空
4. 在筛选里选 **XHR** 或 **Fetch**（列表数据多半在这两类里）
5. **刷新页面**（F5 或 Ctrl+R）

### 2. 找「列表接口」

看列表第一次出来时，多出了哪些请求。重点看：

- **Request URL** 里是否包含：`hots`、`popular`、`article`、`network`、`list`、`page`、`query` 等
- **Response** 预览里是否是 **JSON**，且结构像「数组」或 `{ data: { list: [...] } }` 这种

请记下：

- 列表接口的 **完整 URL**（含 query 参数）
- **Request Method**：GET 还是 POST
- **Request Headers** 里是否有：`Authorization`、`Cookie`、`X-Token` 等（登录/鉴权）
- **Response** 里 JSON 的**大致结构**，例如：
  - `[{ "title": "...", "platform": "...", ... }]`
  - 或 `{ "code": 0, "data": { "list": [ ... ] } }`

若找到这样的接口，**直接用该接口取数**会比用 Playwright 抓 DOM 更稳、更易和「你要的内容」一一对应。

---

## 二、若没有明显列表接口：看 DOM 结构（Elements）

若 Network 里没有明显返回列表的接口（例如数据写在首屏 HTML 或通过 WebSocket 推送），就需要按 DOM 抓。

### 1. 打开 Elements（元素）面板

1. F12 → **Elements**
2. 用左上角「选择元素」箭头点一下**表格里任意一行**（标题、平台、阅读量等）

### 2. 看表格的 HTML 结构

在 Elements 里确认：

- 表格是 **`<table>`** 还是 **div 模拟的表格**（例如 class 含 `el-table`）
- 若是 `<table>`：
  - 行是 `<tr>`，单元格是 `<td>` 吗？
  - 列顺序是否依次为：标题、平台、领域、阅读(播放)、评论量、点赞量、发布时间、操作？
- 若是 **Element Plus 的 el-table**：
  - 实际 DOM 里往往仍是 `<table>`，在 `class="el-table__body"` 或类似容器下
  - 确认 `tbody` 下每一行 `tr` 的 `td` 数量与顺序（有无「空列」、合并列等）

请记下：

- 最外层表格容器的 **class 或 id**（例如 `el-table`、`class="...table..."`）
- **每一行** 的 `tr` 的 class
- **每一列** 对应的索引（第 0 个 td 是标题、第 1 个是平台…）

这样我们才能把「页面上的列」和「你要的字段」精准对应（标题、平台、领域、阅读、评论、点赞、时间等）。

---

## 三、筛选条件对应的请求参数

页面上有：

- 媒体平台、内容类型、内容领域、发布时间、内容排序、关键词

在 Network 里：

1. 先清空请求列表，再在页面上**改一个筛选**（例如换一个「媒体平台」或「发布时间」）
2. 看**新发出去的请求**的 URL 或 **Request Payload**：
   - 若是 GET：参数一般在 Query String（如 `?platform=toutiao&timeRange=1d`）
   - 若是 POST：参数在 Payload 里（JSON 或 form）

记下：

- **参数名**与**取值**（如 `platform`、`contentType`、`domain`、`publishTime`、`sort`、`keyword`）
- 多选时是 **数组**（`tags[]=a&tags[]=b`）还是 **逗号拼接**（`tags=a,b`）

这样后续如果要「按你的筛选条件」去请求接口，就能和页面行为一致。

---

## 四、把分析结果提供给开发

建议整理成一份简短说明，包含：

1. **列表数据来源**
   - 若是接口：完整 URL、Method、必要 Headers、Response 示例（可打码敏感字段）
   - 若是 DOM：表格选择器（如 `table.el-table__body`）、列索引与字段对应关系
2. **筛选参数**：参数名 + 示例值（与页面筛选一致）
3. **你「要的内容」**：希望最终拿到的字段列表（例如：标题、平台、领域、阅读量、评论量、点赞量、发布时间、链接等）

有了以上 F12 分析结果，就可以在爬虫/接口侧做到「页面展示什么、你要什么」和「我们抓取/请求什么」一一对应，精准匹配。

---

## 五、当前实现如何用你的分析结果

- **若在 Network 里找到了列表接口**  
  当前 Java 爬虫已支持「拦截页面发出的 XHR/Fetch 响应」：打开 `https://www.czgts.cn/v1/hots/popular` 时，会自动尝试捕获 URL 中含 `hots`/`popular`/`network`/`article` 的 JSON 响应。若接口返回的是 `{ data: { list: [...] } }` 或直接数组，会优先用这份数据，不再依赖表格 DOM。  
  请把该接口的 **完整 URL、请求方法、必要 Headers** 以及 **Response 里每条数据的字段名**（如 title、platform、category、reads、comments、likes、publishTime 或你们接口实际用的名字）提供给开发，以便做字段映射，和「你要的内容」完全一致。

- **若没有接口、只能抓 DOM**  
  请按第二节确认表格的 **标签与 class**（如 `table`、`el-table__body`）以及 **列顺序**（第几列是标题、平台、领域、阅读量等）。开发会按你提供的结构改选择器和列索引，使抓取结果与页面展示、与你要的字段一一对应。
